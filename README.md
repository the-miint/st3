# SourceTracker3 (`st3`)

A Rust-core, C/C++-facing library that reimplements SourceTracker: Bayesian
estimation, via a collapsed Gibbs sampler, of the source environments that
contributed to a microbial community ("sink").

- **Library only** — no CLI. Consumed from C/C++ via a `cbindgen`-generated header (`st3.h`).
- **Apache Arrow** at the API boundary; sparse **COO** input, dense + COO output.
- Rust workspace: `st3-core` (algorithm), `st3-arrow` (Arrow ⇄ core), `st3-capi` (C ABI).

## Goals

- **Verifiable statistical equivalence** to the R/Python SourceTracker lineage.
- A **clean, simple, well-documented** C API.
- **Performance** — benchmarked, with a regression guard.

## Status

The full pipeline is implemented and tested: sparse preprocessing, the
collapsed-Gibbs estimator, leave-one-out source prediction, the Arrow boundary,
the C ABI (`st3.h`), per-sink parallelism, and a performance regression guard.
Documentation coverage is enforced (`#![deny(missing_docs)]`, runnable
doctests). Development proceeds milestone by milestone, each on its own branch,
test-driven (red/green/refactor), merged to `main` only when the full gate is
green.

## Building & using from C

Build the library (produces a shared library and a static library):

```sh
cargo build --release
# -> target/release/libst3.so   (shared)
# -> target/release/libst3.a    (static)
```

The C header `st3.h` is generated by the build (via `cbindgen`), and a copy is
committed at `crates/st3-capi/include/st3.h` so a consumer can include it
without locating cargo's build directory. The test gate fails if the committed
copy drifts from the generated one; after changing the C ABI surface, refresh
it with:

```sh
make header
# -> crates/st3-capi/include/st3.h
```

The header refers to the Arrow C Data Interface structs (`ArrowArray`,
`ArrowSchema`, `ArrowArrayStream`) without declaring them; declare them before
including it, e.g. by including Arrow's `abi.h`. Then compile and link a C
program against it. Point `-I` at the header's directory and `-L` at the built
library, link `-lst3` (and `-lm`):

```sh
cc -std=c11 -I crates/st3-capi/include my_app.c -L target/release -lst3 -lm -o my_app
LD_LIBRARY_PATH=target/release ./my_app   # or link the static libst3.a
```

A complete, heavily commented walkthrough — build a dataset over the Arrow C
Data Interface, run source attribution, read the dense means and standard
deviations, and drain the per-sink assignment stream — is in
[`crates/st3-capi/examples/usage.c`](crates/st3-capi/examples/usage.c).

## Using from Rust

Rust consumers depend on `st3-core` directly; the flagship entry points
(`predict_sinks`, `predict_loo`, `rarefy_per_sample`, `CountTable::from_coo`,
`simulate_two_source`) carry runnable examples in their rustdoc
(`cargo doc --open`).

## Development

`make test` runs the full gate: formatting, `clippy -D warnings`, the workspace
test suite (unit, integration, doctests, and the C example), a documentation
build with warnings denied, and a benchmark compile check. The same gate runs in
CI on every push and pull request to `main`.

A `pre-commit` hook runs that gate before each commit. Git does not pick it up
from a fresh clone automatically — enable it once per checkout:

```sh
git config core.hooksPath .githooks
```

The minimum supported Rust version is **1.85** for depending on the crates. The
benches and tests need **1.86** (criterion 0.8's own floor), so `make test`
requires 1.86 or newer.
